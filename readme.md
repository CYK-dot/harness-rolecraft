# Rolecraft

Rolecraft 是一套把个人工作方式写成文件、并编译到多个 AI 平台的框架。

## 它要解决的问题

AI 没法按你的判断标准工作。

它能让功能跑通，但写出让底层引用上层概念的代码，原有的分层被破坏；它能写出结构完整的文档，但把文档当成对话的延伸，第三者读不明白。这些问题的共同点是：在当次任务里都不算错误，事后再看才发现不对。

在对话里指正它，一次指正改变的是当次的那一个行为。AI 理解了这条指令，但它的判断方式没有变化，同类问题会以另一种形式再次出现。

## 它怎么做

把判断标准写成文件，编译到目标平台，让 AI 在这些标准下工作。这些文件称为一个**角色**。

```
docwriter/
    readme.md                   这个角色做什么，要减少哪些情况
    adapt/                      编译到各平台时的提示词
    scenarios/                  什么情况下需要处理
    actions/                    这种情况下的做法
    cognitions/                 为什么这样做
```

角色由人和 AI 共用。AI 读它作为工作依据，人读它来判断 AI 会怎么做、以及为什么。出现偏差时，双方讨论的是哪个场景辨识不准、哪份行动不完整、哪条认知不成立，修改后在下一次及同类情形生效。

角色可以在自己的框架内自我进化。认知层分为 memory、knowledge、methodology，由角色自己按它自订的判据把经历逐步提炼上去，不需要框架提供专门的入口。

## 目录结构

```
design.md                       设计文档：它为什么这样设计
examples/docwriter/             示例角色：一份可用的完整角色
LICENSE                         MIT
```

`design.md` 分三章。第一章说明要解决的问题，第二章说明角色的构成与各部分的写法，第三章以 `examples/docwriter/` 为例，走一遍编写、编译、运行的完整过程。

## 从示例开始

`examples/docwriter/` 是一个可以直接用的角色：写好一份文档、准备交付之前，它按常见的行文问题逐条检查；文档被退回之后，它复盘并把这次错误归档，以后不再犯。

读它的顺序与设计文档第二章一致：先看 `readme.md` 了解它做什么，再看 `scenarios/` 与 `actions/` 了解它在什么时候做什么，最后看 `cognitions/` 了解它的判断依据。

要自己写一个角色，从 `readme.md` 加一个场景开始即可，认知层可以留到需要时再补。

## 编译

角色本身不会运行。要让它生效，需要按目标平台的能力把它编译成那里的组件，例如 skill、agent、插件。

编译由 AI 完成。编写者不写插件、不配 hook，而是在 `adapt/` 里说明这个角色要在什么时机起作用、要看到什么样的结果、哪些要求必须满足。剩余的实现方式由 AI 按平台能力决定。

编写者对编译结果负责。这与代码需要配套构建配置是同一件事：源码本身不能运行，编译参数由作者给出，构建结果由作者验收。
