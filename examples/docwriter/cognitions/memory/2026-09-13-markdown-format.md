# 问题背景
## 当时在做什么
与 AI 讨论 Rolecraft 的设计文档。AI 每写一版，开发者改一版。改动的对象包括 `readme.md`、场景文件、行动文件、以及根目录下的设计文档。

## 关键上下文
这不是某一次偶然的编辑。前后十余份文件、跨越多次修改，开发者的版本都保持了同一形态，而 AI 的版本都保持了另一形态。

# 犯了什么错
AI 写出的 markdown 一律留空行：

```markdown
- 功能跑通了，分层被改掉了，当时看不出来，改动多了才发现

- 为了拿到上层的一个数据，让底层直接引用上层的概念

## 层次划分

依赖方向唯一：上层可以依赖下层，下层不得依赖上层。
```

开发者的版本一律不留：

```markdown
- 功能跑通了，分层被改掉了，当时看不出来，改动多了才发现
- 为了拿到上层的一个数据，让底层直接引用上层的概念

## 层次划分
依赖方向唯一：上层可以依赖下层，下层不得依赖上层。
```

开发者没有就这一点提出过意见，我是从十余次改动中看出来的。

# 犯错的直接原因
AI 的书写习惯来自通用 markdown 惯例，以及多数格式化工具与 linter 的默认规则。这些惯例进入上下文后，在没有被要求的情况下自动生效。

# 犯错的根本原因
AI 把"格式正确"当成了默认目标，而没有先确认这个角色服务的人对格式的实际偏好。

格式与内容不同，内容的对错可以从对错本身判断，格式的对错只能从服务对象的习惯判断。AI 没有把后者当成一个需要获取的信息，因此用了通用默认值。

这一点与本角色要减少的其他几种情况同源：AI 的判断依据是"这样做是否合乎常规"，而不是"这样做是否符合读者的实际预期"。
