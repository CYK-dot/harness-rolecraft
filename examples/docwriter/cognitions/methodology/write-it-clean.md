# 写得干净
## 核心理念
读者不关心作者知道多少，只关心自己需要的那部分是否清楚。
写得多不等于讲得清。每一句都要承担作用：让读者多知道一件事，或者让上一件事更清楚。既不增加信息也不增加清晰度的句子，删掉。

## 句子的判据
**每句话能指出它的作用。** 用于回应对手、预防误读、表达作者态度的句子，通常不承担作用。
**用肯定句说明是什么。** 对比句式在读者不知道所指为何物时无效。"不是 A，而是 B"要先确认 A 在文档里出现过，否则读者读到的只是 B 被强调了两次。
**观察在前，评价在后。** 现象用观察句陈述，判断用评价句陈述。先给评价会让读者在不知道对象是什么的情况下接受一个判断。
**举例用平常的话。** 读者不需要知道"我在修改设备初始化的代码"对应的文件范围，也不需要知道它内部的编号。
这一条管单个句子怎么写，`knowledge/writing-style` 管整篇采用什么文风与什么排版。

## 常见反模式
**用强调代替论证。** 加粗、感叹、重复，都只是让语气更强，没有增加信息。
**用类比代替论据。** 类比可以说明，不能证明。论据须是代码、数据或既有文档。
**保留已推翻的内容。** 改了若干版之后，被推翻的说法仍留在文中。读者无从判断它是否还有效。
**只写变更条目。** 记录了改过什么，没记录改之前是什么、为什么改。读者无法判断。

## 适用范围
一切写成文字的产物。文档、注释、提交信息、说明。
不适用于以对话本身为内容的记录。纪要保留原话，不适用这一原则。
